# Learning Workspace

New institution-oriented learning platform, implemented incrementally against [PRODUCT-SPEC.md](PRODUCT-SPEC.md). **The complete platform is not implemented.** The current runnable increment covers part of milestone 1. The [233-requirement register](IMPLEMENTATION-STATUS.md) is the completion authority.

## Run locally

Install Go 1.27.4, Bun 1.4.4 and Docker with Compose. Then:

```sh
bun install --frozen-lockfile
bun run dev
```

Startup generates `.env` with random local credentials, starts PostgreSQL 18.7, private SeaweedFS S3 and Mailpit, applies Goose migrations, initializes synthetic fixtures once, and runs the Go API/worker and Next.js web client.

Open http://localhost:3000. Read `.local/demo-access.txt` for the random synthetic owner credentials. Local invitation/recovery mail appears at http://localhost:58025. These messages are development captures, not live delivery. Stop application processes with Ctrl-C; persisted Docker volumes remain. `docker compose stop` stops the backing services without deleting data.

Do not use real children or financial records in this development installation. Never copy its `.env` to production.

## Current operations

- Sign in with an opaque server session, inspect/revoke sessions, enroll TOTP, save single-use recovery codes, reset passwords and accept invitations.
- Choose institution/campus; create additional institutions, campuses and courses; invite learners, guardians and staff; admit learners with permanent references; approve/remove family links; assign teaching responsibilities.
- Suspend or restore memberships with a reason; suspension revokes existing sessions. Owner removal and self changes fail closed.
- Read institution audit and invitation delivery status; retry failed invitation delivery.

All institutional operations run in Go, with parameterized PostgreSQL transactions and server-side capability checks. There are no implemented academic, finance, AI or native workflows yet. Some English/Hindi interface labels are translated; translation completeness remains open.

## Check

```sh
bun run check
bun run build
# .env contains only local values generated by startup
set -a
source .env
set +a
TEST_DATABASE_URL="$DATABASE_URL" go test -tags=integration -race ./...
bunx playwright install chromium
bun run test:e2e
```

Integration tests create and drop isolated schemas in the supplied PostgreSQL database. Without `TEST_DATABASE_URL` they are explicitly skipped; a unit-only green result is not integration evidence. Browser tests require running services and the synthetic demo. Tests add original synthetic records to the local demo instance.

`bun run generate` produces shared web/native TypeScript API types from [OpenAPI](contracts/openapi.json). After contract authoring changes run `python3 scripts/contract.py` first. No handwritten parallel API type copy is needed.
